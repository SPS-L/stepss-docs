STEPSS comes in [two editions](/getting-started/overview/#two-editions). This page covers **STEPSS for Java**, the desktop application, and the Fortran toolchain needed only if you intend to build your own models.

:::tip[Working from Python instead?]
**STEPSS for Python** installs with a single command and needs no Java:

```bash
pip install stepss
```

It bundles the same RAMSES and Helios engines. See [Python API Installation](/python/installation/) for the full instructions, including the system libraries Linux and macOS need.
:::

The Java edition comes two ways: an **installer**, which carries its own Java and is what most people want, or the **`stepss.jar`** on its own, which needs a Java you already have. Both are on every [release](https://github.com/SPS-L/stepss-java-ui/releases). On Debian and Ubuntu there is a third way, an **APT repository**, which is the same installer delivered so that `apt upgrade` keeps it current.

## Installing STEPSS for Java

<Tabs>
<TabItem label="Installer (recommended)">

The installers bundle a Java runtime, so **nothing else needs installing** and an existing Java on the machine is neither required nor disturbed.

<LinkButton href="https://github.com/SPS-L/stepss-java-ui/releases/latest" icon="cloud-download">Go to the latest release</LinkButton>

<Steps>

1. Download the one for your system from the release's assets:
   - **Windows**: `STEPSS-<version>.msi`
   - **macOS** (Apple Silicon): `STEPSS-<version>.dmg`
   - **Linux** (Debian, Ubuntu): `stepss_<version>_amd64.deb`, though the **Debian and Ubuntu (apt)** tab is the better route if you can use it: same package, and later releases arrive on their own.
2. Open it and follow the installer.
3. Launch **STEPSS** from the Start menu, Applications, or your desktop's application list.

</Steps>

On Linux, install the `.deb` with `sudo apt install ./stepss_<version>_amd64.deb` rather than `dpkg -i`, so that the packages it needs, gnuplot among them, are pulled in with it. It requires **Ubuntu 24.04 or newer**, or a Debian of the same vintage or later; on an older release, use the jar.

Uninstall the way you would any other application on your system: Add or Remove Programs on Windows, dragging it to the Trash on macOS, `sudo apt remove stepss` on Debian and Ubuntu.

</TabItem>
<TabItem label="Debian and Ubuntu (apt)">

STEPSS has an APT repository, so it installs like any other package and every later release arrives through `apt upgrade` instead of being downloaded by hand. It is the same `.deb` as the Installer tab, served from **[apt.sps-lab.org](https://apt.sps-lab.org/)**.

Set it up once:

```bash
sudo install -d -m 0755 /etc/apt/keyrings
sudo curl -fsSL https://apt.sps-lab.org/sps-l-archive-keyring.asc \
  -o /etc/apt/keyrings/sps-l-archive-keyring.asc

sudo tee /etc/apt/sources.list.d/sps-l.sources >/dev/null <<'EOF'
Types: deb
URIs: https://apt.sps-lab.org
Suites: stable
Components: non-free
Architectures: amd64
Signed-By: /etc/apt/keyrings/sps-l-archive-keyring.asc
EOF
```

Then install, and from that point on upgrade with the rest of the system:

```bash
sudo apt update
sudo apt install stepss
```

Run it with `stepss`, or from the Science section of the applications menu. Remove it with `sudo apt remove stepss`.

<Aside type="caution" title="What this route requires and what it is not">
- **Ubuntu 24.04 or newer**, or a Debian of the same vintage or later, on **x86-64**. The package is built on 24.04 and names its dependencies as that release names them, so 22.04 and Debian 12 cannot install it. There is no Linux arm64 build of the engines, which is why `Architectures: amd64` is in the snippet: without that line, apt on an arm64 machine looks for an index that does not exist and errors on every `apt update`.
- **The current release only.** The repository serves one version. To install a specific older build, take its `.deb` from the [releases page](https://github.com/SPS-L/stepss-java-ui/releases).
- **`non-free` is accurate, not boilerplate.** STEPSS is not free software taken as a whole: RAMSES is proprietary and free for non-commercial use only, and Helios and CODEGEN are under Academic Public Licences. Installing through apt agrees to nothing, since the licence appears the first time you launch STEPSS. Read [Licensing](/getting-started/license/) before you run it, and please do not mirror the repository: the licence granted for RAMSES is non-transferable.
- **This is not an official Ubuntu or Debian repository**, and nothing in it has been through Canonical's or Debian's review.
</Aside>

</TabItem>
<TabItem label="Just the jar">

The jar is a single file that leaves nothing behind: it unpacks what it needs into a temporary folder at launch, and deleting the file removes STEPSS entirely. It needs a **64-bit Java Runtime Environment, version 11 or later** already on the machine. Any recent JRE or JDK will do, and there is no need to remove a Java you already have as long as it meets that minimum.

<LinkButton href="https://github.com/SPS-L/stepss-java-ui/releases/latest/download/stepss.jar" icon="cloud-download">Download stepss.jar</LinkButton>

<Steps>

1. **Check for Java**. At a command prompt:
   ```bash
   java -version
   ```
   If that reports a 64-bit Java 11 or later, skip the next step.

2. **Install Java** if it did not: a 64-bit JDK from [Adoptium](https://adoptium.net/) or [oracle.com](https://www.oracle.com/java/technologies/downloads/).

3. **Put the jar** wherever is convenient. Do not uncompress it.

4. **Launch it**, by double-clicking or with:
   ```bash
   java -jar stepss.jar
   ```
   On Windows, if a double-click does nothing, right-click the jar, choose "Open with", and point it at Java.

</Steps>

The jar is the one route that installs nothing alongside itself, so real-time plotting needs gnuplot put there by hand. On Linux that is `sudo apt install gnuplot-x11` (not plain `gnuplot`, which can resolve to a build with no interactive terminal), on macOS `brew install gnuplot`; Windows carries its own copy inside the jar and needs nothing.

</TabItem>
</Tabs>

## Installing a Fortran Toolchain

<Aside type="tip">
This step can be **skipped** if you do not plan to develop new models for RAMSES using CODEGEN. Everything else in STEPSS works without it.
</Aside>

Compiling a custom model produces a simulator built from the bundled URAMSES kit,
which is a **gfortran** build. You therefore need `gfortran`, GNU `make` and
OpenBLAS on your machine.

<Tabs>
<TabItem label="Windows">

Install [MSYS2](https://www.msys2.org/), then from an MSYS2 shell:

```bash
pacman -S mingw-w64-x86_64-gcc-fortran mingw-w64-x86_64-openblas make
```

STEPSS looks for the installation in `C:\msys64`, or wherever the `MSYS2_ROOT`
environment variable points, so the MinGW `bin` directory does not have to be on
the system `PATH`.

</TabItem>
<TabItem label="Linux">

```bash
sudo apt install gfortran make libopenblas-dev     # Debian/Ubuntu
sudo dnf install gcc-gfortran make openblas-devel  # Fedora/RHEL
```

</TabItem>
<TabItem label="macOS">

macOS ships no Fortran compiler, so it comes from [Homebrew](https://brew.sh/):

```bash
brew install gcc openblas
```

Apple Silicon only; Intel Macs are not supported.

</TabItem>
</Tabs>

<Aside type="caution" title="The compiler must match the kit">
Fortran `.mod` files can only be read by the gfortran release that wrote them.
Each platform's default compiler normally matches its own bundled kit; when it
does not, STEPSS reports the exact compiler version to install rather than
failing in the middle of a build. See [URAMSES](/developer/uramses/) for the
details.
</Aside>
