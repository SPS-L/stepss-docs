STEPSS comes in [two editions](/getting-started/overview/#two-editions). **STEPSS GUI** is the desktop application. **STEPSS in Python** is the `stepss` package, which drives the same engines from a script or a notebook and needs no Java. Both read the same data files, so a case built in one runs unchanged in the other.

## Installing STEPSS

STEPSS GUI is published on every [release](https://github.com/SPS-L/stepss-java-ui/releases) as an installer that brings its own Java, so an existing Java on the machine is neither required nor disturbed. Each platform also has a package manager route, recommended where you can use it: it delivers the same application, and later releases arrive with your other updates instead of being downloaded by hand.

Choose your platform, or **Python** for STEPSS in Python:

<Tabs>
<TabItem label="Windows">

Windows on x86-64. There is no Windows arm64 build of the engines.

**Scoop (recommended).** STEPSS has a [Scoop](https://scoop.sh/) bucket. It installs into your own profile and **needs no administrator rights**, so it works on a managed machine where an installer cannot be run. If you do not have Scoop yet, install it in a normal (not elevated) PowerShell:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Invoke-RestMethod -Uri https://get.scoop.sh | Invoke-Expression
```

Then add the bucket once and install:

```powershell
scoop bucket add sps-l https://github.com/SPS-L/stepss-scoop
scoop install stepss
```

Upgrade with `scoop update stepss` and remove with `scoop uninstall stepss`. You get STEPSS on the Start menu under **Scoop Apps**, an icon on your desktop, and a `stepss` command on your `PATH`.

**Installer.** Download `STEPSS-<version>.msi` from the release's assets, open it and follow the installer. Remove it from Add or Remove Programs.

<LinkButton href="https://github.com/SPS-L/stepss-java-ui/releases/latest" icon="cloud-download">Go to the latest release</LinkButton>

**Compiling your own models.** Neither Windows route installs a Fortran toolchain, because nothing but compiling your own models needs one. Install [MSYS2](https://www.msys2.org/), or run `scoop install msys2`, and from an MSYS2 shell:

```bash
pacman -S mingw-w64-x86_64-gcc-fortran mingw-w64-x86_64-openblas make
```

STEPSS finds MSYS2 in `C:\msys64`, in Scoop's applications directory, or wherever the `MSYS2_ROOT` environment variable points, so there is nothing to configure by hand.

</TabItem>
<TabItem label="macOS">

Apple Silicon. There is no Intel macOS build of the engines.

**Homebrew (recommended).** STEPSS has a [Homebrew](https://brew.sh/) tap. It also installs `gcc` and `openblas`, which the simulation engines load at run time and which compiling your own models needs:

```bash
brew install --cask sps-l/stepss/stepss
```

Upgrade with `brew upgrade --cask stepss` and remove with `brew uninstall --cask stepss`. If STEPSS is already in Applications from a `.dmg`, move it to the Trash first: Homebrew does not overwrite an application it did not install.

**Installer.** Download `STEPSS-<version>.dmg` from the release's assets and drag STEPSS to Applications. The `.dmg` cannot bring the two Homebrew packages with it, so install them once yourself, or the application opens normally and the first simulation fails:

```bash
brew install gcc openblas
```

Remove it by dragging it to the Trash.

<LinkButton href="https://github.com/SPS-L/stepss-java-ui/releases/latest" icon="cloud-download">Go to the latest release</LinkButton>

The application is signed and notarized, and macOS confirms that with Apple the first time you open it, so that first launch needs a network connection.

</TabItem>
<TabItem label="Debian and Ubuntu">

**Debian and Ubuntu are the Linux distributions STEPSS is packaged for**: Ubuntu 24.04 or newer, or a Debian of the same vintage or later, on x86-64. The package names its dependencies as 24.04 names them, so Ubuntu 22.04 and Debian 12 cannot install it, and no package is produced for any other distribution or architecture.

**APT repository (recommended).** STEPSS has an APT repository at **[apt.sps-lab.org](https://apt.sps-lab.org/)**. Set it up once:

```bash
sudo install -d -m 0755 /etc/apt/keyrings
sudo curl -fsSL https://apt.sps-lab.org/sps-l-archive-keyring.asc \
  -o /etc/apt/keyrings/sps-l-archive-keyring.asc

sudo tee /etc/apt/sources.list.d/sps-l.sources >/dev/null <<'EOF'
Types: deb
URIs: https://apt.sps-lab.org
Suites: stable
Components: non-free
Architectures: amd64
Signed-By: /etc/apt/keyrings/sps-l-archive-keyring.asc
EOF
```

Then install, and from that point on upgrade with the rest of the system:

```bash
sudo apt update
sudo apt install stepss
```

`Architectures: amd64` is needed: without it, apt on an arm64 machine looks for an index that does not exist and errors on every `apt update`. `Components: non-free` is accurate, since RAMSES is proprietary.

:::caution[If `apt update` says `NO_PUBKEY 3600A756077AD061`]
apt could not find the key, for one of three reasons: the keyring file is **not there** (the download failed, and `curl` writes nothing when it does), the `Signed-By` line is missing from your `.sources` file, or the file holds another key. Check it with:

```bash
gpg --show-keys /etc/apt/keyrings/sps-l-archive-keyring.asc
```

It should print fingerprint `125ABE6917ED2F2965D6545B3600A756077AD061` for `SPS-L Packaging <stepss@sps-lab.org>`. If it reports no such file, or complains about `add_keyblock_resource` (an empty file), run the `curl` command again.
:::

**Installer.** Download `stepss_<version>_amd64.deb` from the release's assets and install it with apt rather than `dpkg -i`, so that its dependencies come with it:

```bash
sudo apt install ./stepss_<version>_amd64.deb
```

<LinkButton href="https://github.com/SPS-L/stepss-java-ui/releases/latest" icon="cloud-download">Go to the latest release</LinkButton>

Both routes also install `gfortran`, `make` and `libopenblas-dev` as recommended packages, which compiling your own models needs. Run STEPSS with `stepss`, or from the Science section of the applications menu, and remove it with `sudo apt remove stepss`.

</TabItem>
<TabItem label="Python">

**STEPSS in Python** is the `stepss` package on PyPI. It needs Python 3:

```bash
pip install stepss
```

The package carries pre-compiled RAMSES and Helios binaries for Windows, Linux and macOS, so there is nothing to install alongside it. On Linux and macOS those binaries link against system runtime libraries (OpenBLAS, the gfortran and OpenMP runtimes) that your machine may not already have; the [Python API Installation Guide](/python/installation/) lists them, and covers version pinning.

`stepss` does not carry CODEGEN, so **writing your own models needs STEPSS GUI** or [CODEGEN Studio](#installing-codegen-studio). Running a model someone else compiled works from either edition.

</TabItem>
</Tabs>

<Aside type="caution" title="What the package manager routes are and are not">
- **They serve the current release only.** To install an older build, take its installer from the [releases page](https://github.com/SPS-L/stepss-java-ui/releases).
- **They are ours, not the distributions'.** The APT repository, the Scoop bucket and the Homebrew tap are not official, and nothing in them has been through Canonical's, Debian's, Scoop's or Homebrew's review.
- **Installing through them agrees to nothing.** STEPSS is not free software taken as a whole: the licence appears the first time you launch it. Read [License](/getting-started/license/) before you run it, and do not mirror the packages, since the licence granted for RAMSES is non-transferable.
</Aside>

Compiling your own models also needs the gfortran release that matches the bundled kit; [URAMSES](/developer/uramses/#prerequisites) covers that check.

## Installing CODEGEN Studio

[CODEGEN Studio](/developer/cg-studio/) is the browser-based visual editor for building models: drag blocks onto a canvas, connect them, and export a model file instead of writing one by hand. It is its own Python package, `stepss-cg-studio`, tied to neither edition, and needs **Python 3.10 or newer**. [CODEGEN Studio](/developer/cg-studio/) gives the install command, the command-line options and a source install.

Its wheel carries the CODEGEN executables for Linux, Windows and macOS, so it generates Fortran on a fresh install. On macOS it also needs Homebrew's `gcc`, which either macOS route above already installs. CODEGEN is not Apache 2.0 like the editor around it: see [License](/getting-started/license/#codegen-license).
