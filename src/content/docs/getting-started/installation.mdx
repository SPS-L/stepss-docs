STEPSS comes in [two editions](/getting-started/overview/#two-editions), and this page installs either. **STEPSS GUI** is the desktop application: install it once, then work from windows and menus. **STEPSS in Python** is the `stepss` package: `pip install` it and drive the same engines from a script or a notebook. Both read the same data files, so a case built in one runs unchanged in the other, and installing one does not commit you to it.

The last two sections, the Fortran toolchain and CODEGEN Studio, are for writing your own models. Skip them unless you intend to.

:::tip[Only want the Python package?]
`pip install stepss` is the whole installation and it needs no Java. Skip to [Installing STEPSS in Python](#installing-stepss-in-python).
:::

## Installing STEPSS GUI

STEPSS GUI comes two ways: an **installer**, which carries its own Java and is what most people want, or the **`stepss.jar`** on its own, which needs a Java you already have. Both are on every [release](https://github.com/SPS-L/stepss-java-ui/releases). On Debian and Ubuntu there is a third way, an **APT repository**, which is the same installer delivered so that `apt upgrade` keeps it current.

:::note[Which Linux]
**Debian and Ubuntu are the Linux distributions STEPSS is packaged for**, from Ubuntu 24.04 and its Debian contemporary onwards, on x86-64. That is what the `.deb` and the APT repository are built and tested against, and no package is produced for any other distribution or architecture.

On anything else, including older Debian and Ubuntu releases, use **`stepss.jar`**. It needs a 64-bit Java 11 or later and gnuplot from your own package manager, and it carries the same engines. It is not tested there, but nothing in it is Debian-specific.
:::

<Tabs>
<TabItem label="Installer (recommended)">

The installers bundle a Java runtime, so **nothing else needs installing** and an existing Java on the machine is neither required nor disturbed.

<LinkButton href="https://github.com/SPS-L/stepss-java-ui/releases/latest" icon="cloud-download">Go to the latest release</LinkButton>

<Steps>

1. Download the one for your system from the release's assets:
   - **Windows**: `STEPSS-<version>.msi`
   - **macOS** (Apple Silicon): `STEPSS-<version>.dmg`
   - **Linux** (Debian, Ubuntu): `stepss_<version>_amd64.deb`, though the **Debian and Ubuntu (apt)** tab is the better route if you can use it: same package, and later releases arrive on their own.
2. Open it and follow the installer.
3. Launch **STEPSS** from the Start menu, Applications, or your desktop's application list.

</Steps>

On Linux, install the `.deb` with `sudo apt install ./stepss_<version>_amd64.deb` rather than `dpkg -i`, so that the packages it needs, gnuplot among them, are pulled in with it. It requires **Ubuntu 24.04 or newer**, or a Debian of the same vintage or later; on an older release, use the jar.

Uninstall the way you would any other application on your system: Add or Remove Programs on Windows, dragging it to the Trash on macOS, `sudo apt remove stepss` on Debian and Ubuntu.

</TabItem>
<TabItem label="Debian and Ubuntu (apt)">

STEPSS has an APT repository, so it installs like any other package and every later release arrives through `apt upgrade` instead of being downloaded by hand. It is the same `.deb` as the Installer tab, served from **[apt.sps-lab.org](https://apt.sps-lab.org/)**.

Set it up once:

```bash
sudo install -d -m 0755 /etc/apt/keyrings
sudo curl -fsSL https://apt.sps-lab.org/sps-l-archive-keyring.asc \
  -o /etc/apt/keyrings/sps-l-archive-keyring.asc

sudo tee /etc/apt/sources.list.d/sps-l.sources >/dev/null <<'EOF'
Types: deb
URIs: https://apt.sps-lab.org
Suites: stable
Components: non-free
Architectures: amd64
Signed-By: /etc/apt/keyrings/sps-l-archive-keyring.asc
EOF
```

Then install, and from that point on upgrade with the rest of the system:

```bash
sudo apt update
sudo apt install stepss
```

Run it with `stepss`, or from the Science section of the applications menu. Remove it with `sudo apt remove stepss`.

:::caution[If `apt update` says `NO_PUBKEY 3600A756077AD061`]
That is apt naming the key it wanted and could not find, and it means one of three things, which look identical from apt: the keyring file is **not there**, because the download failed and `curl` correctly writes nothing when it does; the `Signed-By` line is missing from your `.sources` file; or the file holds some other key.

```bash
gpg --show-keys /etc/apt/keyrings/sps-l-archive-keyring.asc
```

It should print fingerprint `125ABE6917ED2F2965D6545B3600A756077AD061` for `SPS-L Packaging <stepss@sps-lab.org>`. If it reports no such file, run the `curl` command again. A different complaint mentioning `add_keyblock_resource` means the file exists but is empty, and has the same remedy.
:::

<Aside type="caution" title="What this route requires and what it is not">
- **Ubuntu 24.04 or newer**, or a Debian of the same vintage or later, on **x86-64**. The package is built on 24.04 and names its dependencies as that release names them, so 22.04 and Debian 12 cannot install it. There is no Linux arm64 build of the engines, which is why `Architectures: amd64` is in the snippet: without that line, apt on an arm64 machine looks for an index that does not exist and errors on every `apt update`.
- **The current release only.** The repository serves one version. To install a specific older build, take its `.deb` from the [releases page](https://github.com/SPS-L/stepss-java-ui/releases).
- **`non-free` is accurate, not boilerplate.** STEPSS is not free software taken as a whole: RAMSES is proprietary and free for non-commercial use only, and Helios and CODEGEN are under Academic Public Licences. Installing through apt agrees to nothing, since the licence appears the first time you launch STEPSS. Read [Licensing](/getting-started/license/) before you run it, and please do not mirror the repository: the licence granted for RAMSES is non-transferable.
- **This is not an official Ubuntu or Debian repository**, and nothing in it has been through Canonical's or Debian's review.
</Aside>

</TabItem>
<TabItem label="Just the jar">

The jar is a single file that leaves nothing behind: it unpacks what it needs into a temporary folder at launch, and deleting the file removes STEPSS entirely. It needs a **64-bit Java Runtime Environment, version 11 or later** already on the machine. Any recent JRE or JDK will do, and there is no need to remove a Java you already have as long as it meets that minimum.

<LinkButton href="https://github.com/SPS-L/stepss-java-ui/releases/latest/download/stepss.jar" icon="cloud-download">Download stepss.jar</LinkButton>

<Steps>

1. **Check for Java**. At a command prompt:
   ```bash
   java -version
   ```
   If that reports a 64-bit Java 11 or later, skip the next step.

2. **Install Java** if it did not: a 64-bit JDK from [Adoptium](https://adoptium.net/) or [oracle.com](https://www.oracle.com/java/technologies/downloads/).

3. **Put the jar** wherever is convenient. Do not uncompress it.

4. **Launch it**, by double-clicking or with:
   ```bash
   java -jar stepss.jar
   ```
   On Windows, if a double-click does nothing, right-click the jar, choose "Open with", and point it at Java.

</Steps>

The jar is the one route that installs nothing alongside itself, so real-time plotting needs gnuplot put there by hand. On Linux that is `sudo apt install gnuplot-x11` (not plain `gnuplot`, which can resolve to a build with no interactive terminal), on macOS `brew install gnuplot`; Windows carries its own copy inside the jar and needs nothing.

</TabItem>
</Tabs>

:::note[There is no separate command-line install]
The [Quick Start](/getting-started/quickstart/) shows `ramses`, `helios` and
`codegen` being driven from a shell, and those executables reach you through an
edition rather than on their own. STEPSS GUI carries all four, `dyngraph`
included, and unpacks them into a temporary folder it clears again on exit, so
they are not left behind on your `PATH`. `stepss` embeds RAMSES and Helios as
libraries it calls in-process, so there is nothing to invoke from a shell there
either. Installing either edition gets you everything those commands do,
through that edition's own interface.
:::

## Installing STEPSS in Python

**STEPSS in Python** is the `stepss` package on PyPI. It needs Python 3 and no Java at all:

```bash
pip install stepss
```

That one command brings the engines with it: the package carries pre-compiled RAMSES and Helios binaries for Windows, Linux and macOS, so there is nothing to install alongside it and nothing to point it at. Trajectory plotting is built in, on top of Matplotlib, in place of the DYNGRAPH viewer the GUI launches.

Two things it does not do for you, both covered by the [Python API Installation Guide](/python/installation/): on Linux and macOS the bundled binaries link against system runtime libraries (OpenBLAS, the gfortran and OpenMP runtimes) that your machine may not already have, and real-time plotting during a simulation wants gnuplot on your `PATH`. That page also covers version pinning, which is how you fix the engine version a script runs against.

:::note[CODEGEN is not in this edition]
`stepss` bundles RAMSES and Helios, not CODEGEN, so **writing your own models needs STEPSS GUI** or the toolchain below. Running a model someone else compiled works from either edition. [Two Editions](/getting-started/overview/#two-editions) sets out what each one carries.
:::

## Installing a Fortran Toolchain

<Aside type="tip">
This step can be **skipped** unless you intend to compile your own models. Both editions run their bundled engines, and every model already in them, without it.
</Aside>

Compiling a custom model produces a simulator built from the bundled URAMSES kit,
which is a **gfortran** build. You therefore need `gfortran`, GNU `make` and
OpenBLAS on your machine.

This applies to **either edition**: [URAMSES](/developer/uramses/) links custom
models into `stepss` and into STEPSS GUI alike. It is the compiling that needs a
toolchain, and it is separate from writing the model in the first place, which is
CODEGEN's job and ships only with the GUI.

<Tabs>
<TabItem label="Windows">

Install [MSYS2](https://www.msys2.org/), then from an MSYS2 shell:

```bash
pacman -S mingw-w64-x86_64-gcc-fortran mingw-w64-x86_64-openblas make
```

STEPSS looks for the installation in `C:\msys64`, or wherever the `MSYS2_ROOT`
environment variable points, so the MinGW `bin` directory does not have to be on
the system `PATH`.

</TabItem>
<TabItem label="Linux (Debian, Ubuntu)">

```bash
sudo apt install gfortran make libopenblas-dev
```

Installing STEPSS through [apt](#installing-stepss-gui) offers these three
as recommended packages, so on that route they are already there unless you
declined them.

</TabItem>
<TabItem label="macOS">

macOS ships no Fortran compiler, so it comes from [Homebrew](https://brew.sh/):

```bash
brew install gcc openblas
```

Apple Silicon only; Intel Macs are not supported.

</TabItem>
</Tabs>

<Aside type="caution" title="The compiler must match the kit">
Fortran `.mod` files can only be read by the gfortran release that wrote them.
Each platform's default compiler normally matches its own bundled kit; when it
does not, STEPSS reports the exact compiler version to install rather than
failing in the middle of a build. See [URAMSES](/developer/uramses/) for the
details.
</Aside>

## Installing CODEGEN Studio

[CODEGEN Studio](/developer/cg-studio/) is the browser-based visual editor for
building models: drag blocks onto a canvas, connect them, and export a DSL file
instead of writing one by hand. It is its own Python package, tied to neither
edition, and needs **Python 3.10 or newer**:

```bash
pip install stepss-cg-studio
cg-studio
```

`cg-studio` starts a local server and opens the editor at
`http://localhost:8765`. If the script is not on your `PATH`,
`python -m cg_studio` does the same thing. Browser-based here means the
interface is a web page, not that anything leaves your machine: the server is
local and so is every file it reads.

<Aside type="note" title="The editor is not the compiler">
The wheel carries the editor alone, so the **Run Codegen** button needs a
`codegen` executable you point Settings (the gear icon) at. Leaving it unset
costs you nothing much: exporting the DSL file is what the editor is for, and
STEPSS GUI runs CODEGEN over that file without any of this. See
[User-Defined Models](/developer/user-models/) for what happens to it next.
</Aside>

See [CODEGEN Studio](/developer/cg-studio/) for the command-line options, a
source install, and how to drive the editor itself.
